# 是非钟 BLE 通信协议（当前固件）

请 App 端按下面的 UUID 和字节布局实现。所有多字节整数均为 little-endian。

## GATT

设备名：`是非钟-0001`（后缀可能随固件配置变化）

主服务：`d38a0001-1234-5678-9abc-def012345678`

| 特征 | UUID | 属性 | 方向 |
|---|---|---|---|
| Event | `d38a0002-1234-5678-9abc-def012345678` | Read, Notify | 手表 → App |
| Control | `d38a0003-1234-5678-9abc-def012345678` | Read, Write | App → 手表 |
| Data | `d38a0004-1234-5678-9abc-def012345678` | Read, Notify | 手表 → App |
| Status | `d38a0005-1234-5678-9abc-def012345678` | Read, Notify | 手表 → App |

通知订阅必须写 CCCD：`00002902-0000-1000-8000-00805f9b34fb`，值为
`01 00`。建议依次订阅 Event、Data、Status，前一个
`onDescriptorWrite` 完成后再写下一个。

## Event 通知（11 字节）

| 偏移 | 长度 | 含义 |
|---:|---:|---|
| 0 | 1 | 协议版本，当前 `0x01` |
| 1 | 1 | 事件类型 |
| 2..3 | 2 | 序号 uint16，little-endian，每次通知递增 |
| 4..7 | 4 | 单调时钟毫秒 uint32，little-endian |
| 8 | 1 | 风险：`0` 低、`1` 中、`2` 高 |
| 9 | 1 | 置信度 `0..100` |
| 10 | 1 | flags |

事件类型：

| 值 | 含义 |
|---:|---|
| `0x01` | 跌倒 |
| `0x02` | SOS 按键 |
| `0x03` | 心率异常（预留） |
| `0x04` | 血氧过低（预留） |
| `0x05` | 睡眠事件 |
| `0x06` | 电量低 |
| `0x07` | 情绪事件已确认（用户在手表弹窗点“确认”） |
| `0x08` | 情绪事件误报（用户在手表弹窗点“误报”） |
| `0xff` | 自检/台架测试 |

flags：

- `bit 0`（`0x01`）：App 应向 Control 写入 ACK `01`。
- `bit 7`（`0x80`）：台架/模拟事件。

当前手表发送普通事件时可能带 `flags=0x01|0x80`；发送用户确认结果时
`flags=0`，不需要 ACK。`0x07/0x08` 的序号和时间戳仍然正常递增，
App 应把它们作为对最近一次情绪事件的结果更新，而不是新的传感器采样。

## Data 通知（16 字节，每秒）

| 偏移 | 长度 | 含义 |
|---:|---:|---|
| 0..1 | 2 | GSR/皮电 mV，uint16 LE |
| 2 | 1 | 心率 bpm；当前无光学模块，始终 0 |
| 3 | 1 | SpO2 %；当前无光学模块，始终 0 |
| 4 | 1 | flags |
| 5 | 1 | 麦克风相对强度 `0..100` |
| 6 | 1 | 电量百分比 `0..100`，未知为 `0xff` |
| 7..8 | 2 | 加速度 X，int16 LE，mg |
| 9..10 | 2 | 加速度 Y，int16 LE，mg |
| 11..12 | 2 | 加速度 Z，int16 LE，mg |
| 13..14 | 2 | 旋转幅度，uint16 LE，0.1°/s |
| 15 | 1 | 融合情绪：bit7=`1` 表示紧张，bits0..6 为置信度 |

Data flags：`0x01` GSR 有效，`0x08` 麦克风有效，`0x10` 电量有效，
`0x20` IMU 有效，`0x40` GSR 基线已建立。未置位字段应按无效处理。

## Status 通知（16 字节）

| 偏移 | 长度 | 含义 |
|---:|---:|---|
| 0 | 1 | 版本 `0x01` |
| 1 | 1 | flags：`0x01` GSR 有效，`0x10` 电量有效 |
| 2..3 | 2 | GSR mV，uint16 LE |
| 4 | 1 | 心率（当前 0） |
| 5 | 1 | SpO2（当前 0） |
| 6..11 | 6 | 保留，0 |
| 12 | 1 | 电量百分比；无效时 `0xff` |
| 13..15 | 3 | 保留，0 |

## Control 写入

Control 特征写入的第 1 个字节是命令：

- `01`：ACK，确认收到需要 ACK 的 Event。
- `02`：清除手表当前 Event 值。
- `03 xx`：设置上报周期为 `xx` 秒（当前固件保留此接口）。

写入成功后无需等待手表回包；手表会在内部记录最近一次 Control 写入。

## 典型流程

1. 扫描并连接，发现主服务 UUID。
2. 订阅 Event、Data、Status 三个 Notify 特征。
3. 收到普通 Event 且 `flags & 0x01 != 0` 时写 Control：`01`。
4. 收到 Data 后更新实时 GSR/情绪状态。
5. 手表弹窗确认后，收到 Event type `0x07`（确认）或 `0x08`（误报），
   更新 App 中最近一次情绪记录。
